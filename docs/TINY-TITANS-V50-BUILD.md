# Tiny Titans Reptile Companion — Full 50 Build

## Mission

Build Tiny Titans as a fast, keeper-first reptile operating system: every important workflow is complete, every internal destination resolves, every complex feature opens as a real route/page, and intelligence connects records rather than creating isolated gimmicks.

## Non-negotiable product rules

1. No dead destinations.
2. No doom-scroll navigation: distinct destinations open distinct routes/pages; local tabs are used only inside a domain.
3. Crisp by default: progressive disclosure hides complexity until useful.
4. Intelligence is explainable: non-trivial insights expose why, evidence, confidence and freshness.
5. Never invent certainty: unknown genetics, inferred phenotype, population data and observations stay explicitly separated.
6. Anticipate useful next actions from state, history, intent and unfinished workflows.
7. Performance is a feature: lazy-load heavy routes, deduplicate reads, cache stable reference data, aggregate intelligence and bound large lists.
8. Private data stays private unless explicitly consented and eligible for aggregation.
9. Health intelligence flags patterns and follow-up actions; it does not diagnose.
10. Desktop and mobile are first-class.

## Intelligent anticipation model

The proactive layer should reason from current state + historical pattern + recent user intent + unfinished workflow + configured preferences.

Examples:

- Weight recorded → surface the most relevant next care workflow based on the keeper's established routine.
- New confirmed morph → offer affected breeding outcome recalculation.
- Partial/problematic shed → offer the appropriate follow-up record.
- Repeated navigation pattern → promote that destination for the specific snake/session.
- Morph synonym search → resolve to the canonical record and retain the relationship.
- New enclosure → surface the species-aware enclosure workflow.

All proactive behaviour must remain explainable and user-controllable.

## Navigation contract

Use route-first navigation. A distinct conceptual destination gets a distinct route.

- Home is a command centre, not a dumping ground.
- Feature hubs use compact tiles/cards to open dedicated pages.
- Dedicated pages use local tabs where they reduce repeated navigation inside the same domain.
- Back/close returns to the initiating context.
- Deep links render directly after refresh.
- Missing destinations fail closed to a useful not-found/unsupported state, never blank output.
- Navigation labels and routes should come from a single registry where practical.

## Performance contract

- Lazy-load heavyweight routes and 3D/Globe modules.
- Prevent duplicate reads caused by parent + child components fetching identical data.
- Prefer pre-aggregated intelligence snapshots for dashboards.
- Cache stable species/morph reference data locally where safe.
- Virtualise or paginate large collections.
- Compress uploaded media and render responsive image sizes.
- Keep 3D/Globe code off the Home critical path where possible.
- Clean event subscriptions on unmount.
- Keep loading/empty/error states visually stable.

## Quality gates

Every major change must preserve the existing validation family: TypeScript/build, route contracts/coverage, morph and species integrity, security/privacy, intelligence consent/journey, notifications, UI hardening, encoding/copy quality and visual/route bot coverage.

## Delivery order

### Phase 1 — Stabilise
Navigation registry, page shells, dead-link audit, route audit, common loading/empty/error states, data access consolidation and performance profiling.

### Phase 2 — Intelligence spine
Event taxonomy, durable intelligence records, recommendation engine, explainability, confidence/evidence/freshness and proactive action selection.

### Phase 3 — Genetics graph
Canonical morph resolver, aliases, evidence ladder, conflicts, lineage graph, what-if engine and breeding feedback.

### Phase 4 — Husbandry intelligence
Digital twin, microclimate-ready data model, anomaly detection, escape/emergency workflows and bioactive/plant modules.

### Phase 5 — Community and learning
Knowledge graph, census/benchmarks, contribution reputation, adaptive learning and annual summaries.

### Phase 6 — Polish
Mobile optimisation, bundle splitting, accessibility, offline room workflows, visual consistency and final HOLY SHIT moments.

## Definition of done

A feature is complete only when its route, loading state, empty state, error state, permissions, persistence, navigation, responsive layout, intelligence integration, tests/contracts and performance behaviour are accounted for.
